## 四、RAG（过关，三题全对）

要点：RAG = Retrieval-Augmented Generation（检索增强生成）= 你的笔记 + 检索 + 模型回答。像开卷考试。解决"模型不知道你的私有数据"。

**两阶段**：
- 准备（一次）：笔记 → 切片 → 转向量(embedding) → 存向量库(chromadb)
- 提问（每次）：问题 → 转向量 → 检索相近片段 → 片段+问题拼起来 → 发模型 → 出答案

**embedding**：文字→一串数字（意思指纹）；意思相近→数字相近；所以按数字距离就能按"意思"检索，绕开关键词不匹配的盲区（"咖啡店经营"vs"社区小店留住熟客"）。用现成工具，不自己实现算法。

**切片三个作用**：装得下（控制窗口）、检索准（精确命中相关段）、省钱（token 少）。

**RAG vs 微调**：RAG 临时给资料不改模型、成本低、适合知识类；微调永久改模型、成本高、适合改行为风格。用户现在只需 RAG。

## 五、概念追问（用户高频问，值得记）

用户今天把 gen_content.py 逐行深挖了两小时，从语法到流程全通。追问列表（都已解答）：
- `f.read().strip()` 哪来的 → 链式调用：read()返回字符串，字符串再调strip()
- 结果赋值给f吗 → 不赋值，f始终是文件对象；return是交出，调用处用 key= 接住
- `as f` 是赋值还是访问 → 把open返回的文件对象绑定到名字f；f≠路径
- read/strip 这类方法还有哪些 → 按对象分类：str.strip/split/lower/upper/replace；list.append/pop；dict.get/keys/values；文件read/write/close。内置函数（len/print）vs 方法（对象.方法）
- 请求头四项 → Authorization(固定头名)+Bearer(认证方案词)+key(自己的)；Content-Type(固定头名)+application/json(值之一，会变)
- 为什么请求头 → 身份认证(实测假key→401)+说明格式+附带信息；快递信封类比
- 请求体四项 → model选模型/messages对话列表套字典(role+content)/stream流式/thinking嵌套字典
- content字符串拼接 → 三段字符串用+拼；+是把变量值"套进"句子的动作（用户核心疑问：理解"套进去"对，但不知道代码里用+表示）
- 不带加号 → SyntaxError，实测；+两边文字是拼接不是加法
- `+主题+` 拼什么 → input()读进来的文字，运行时才确定
- 键名能否改(moxing/model/stream/thinking/type) → 给服务器看的键名照抄，值在官方选项里换
- 变量名能改吗(person/key/r/data/e) → 都能改，前后一致即可；用户已能主动应用这条规则（as e 改成 as a 就都用 a）
- type(e).__name__, e → 显示错误类型(干净名字)+错误详情；type(e),e 也能跑但带<class>不好看
- `.json()` 是响应json格式吗 → 是把响应文本翻译成字典的动作（json.dump的反向）
- content键名哪来的 → 服务器返回数据里自带；查文档或print(数据)探查（实测打印出choices/message/content结构）
